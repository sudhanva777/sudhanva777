## 👋 About Me

Every backend system I like has the same shape: a request lands, gets validated, runs through business logic, touches a database, and leaves as a clean response. I like living in that middle part — the part most users never see, and the part that decides whether the whole system actually holds up.

I'm a **Python backend engineer** with about a year of hands-on experience building REST APIs, working with relational databases, and shipping small backend systems end to end. I also bring practical ML knowledge to the table — when a product genuinely needs a model behind an endpoint, I can build that too, not just prototype it in a notebook.

---

## 🧩 What I Build

- REST APIs that model real business logic, not just CRUD wrappers
- Backend services with proper authentication, validation, and error handling
- Systems that talk to relational databases and stay maintainable as they grow
- Backend layers that can host a trained ML model behind a clean endpoint, when the product actually calls for one

## ⚙️ Backend Engineering

Python is where I start, but the backend is where I live.

- Designing and building REST APIs with **FastAPI** and **Flask** — routing, request/response models, and status codes that actually mean something
- Implementing **authentication & authorization** (JWT-based) and input validation
- Structuring **exception handling and logging** so failures are traceable instead of silent
- Writing modular, testable code instead of one script that "just works"
- Thinking in terms of architecture — what belongs in the route, what belongs in a service layer, what belongs in the database

---

## 🗄️ Data & Database Layer

A backend is only as good as the data layer underneath it.

- Designing relational schemas in **PostgreSQL** and **SQLite** — tables, relationships, and constraints that reflect the actual domain
- Writing and optimizing SQL for real CRUD workloads
- Using **SQLAlchemy** for data persistence and cleaner data access patterns
- Using **Pandas** and **NumPy** when a backend needs to process or reshape data before it hits the database or the response

---

## 🤖 AI/ML Integration

I don't lead with this, but I can back it up.

I use **scikit-learn**, **XGBoost**, and **TensorFlow/Keras** to build and evaluate models, and **OpenCV** / **MediaPipe** for computer vision tasks — then wire the trained model into a backend service so it's actually reachable through an endpoint, not stuck in a notebook. It's one more capability in the toolbox for when a project genuinely needs intelligence, not the default answer to everything.

## 🚀 Featured Projects

**🔐 Security Monitoring Platform (Mini SOC)**
A backend-only security event monitoring system — no ML involved, just architecture. Built with **FastAPI**, **PostgreSQL**, and **Redis**, using **WebSockets** for real-time event streaming and **JWT** for authenticated access, containerized end to end with **Docker**.

**🕵️ Fraud & Anomaly Detection API**
A REST API that wraps a trained anomaly-detection model behind clean, versioned endpoints — request validation in, structured JSON out. The backend does the heavy lifting; the model is just one dependency it calls.

**🗂️ Enterprise File Storage API**
A pure backend service for storing, retrieving, and managing files with proper metadata handling and access control, built to show that not every good project needs ML to be interesting.

**🗣️ German Voice Tutor — Backend**
A fully local, voice-to-voice backend built with **FastAPI** and **asyncio**, orchestrating speech-to-text (Faster-Whisper), a local LLM (Mistral 7B via Ollama), and text-to-speech (Piper) into one real-time pipeline — backend engineering doing the coordination work around AI models, not the other way around.
